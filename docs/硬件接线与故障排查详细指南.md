# 详细硬件接线方案与故障排查指南

## 1. Radxa ROCK 3B 到 STM32 通信链路

### 1.1 UART连接（推荐方案1：直接GPIO）

```
Radxa ROCK 3B         STM32F407
────────────────────────────────
GPIO UART0 TX ─────► USART1_RX (PA10)
GPIO UART0 RX ◄───── USART1_TX (PA9)
GND ──────────────────► GND

波特率: 115200
数据位: 8
校验位: 无
停止位: 1
流控: 无
```

### 1.2 UART连接（备选方案2：USB转TTL模块）

如果Radxa GPIO UART不可靠，使用USB转TTL模块：

```
USB转TTL模块（如CP2102、CH340）
  TX ─────► STM32 USART1_RX (PA10)
  RX ◄───── STM32 USART1_TX (PA9)
  GND ──────► GND
  +5V ──────► （不接，使用STM32的3.3V）

Radxa ROCK 3B
  USB ──────► USB转TTL模块
  GND ──────► USB模块GND（共地）
```

### 1.3 PS2手柄接收器连接（STM32旁路模式）

如果你希望在 **不依赖 Radxa ROCK 3B** 的情况下直接控制麦轮底盘，可以给 STM32 再接一个 PS2 无线接收器。

当前固件默认接线如下：

| PS2接收器引脚 | STM32默认引脚 | 说明 |
|---|---|---|
| `ATT / CS` | `PC0` | 帧选通信号 |
| `CMD` | `PC1` | STM32 发命令 |
| `CLK` | `PC2` | STM32 输出时钟 |
| `DAT` | `PC3` | 接收器回传数据 |
| `VCC` | `3.3V` | 优先使用 3.3V 供电 |
| `GND` | `GND` | 共地 |
| `ACK` | 不接 | 当前代码未使用 |
| `MOTOR` | 不接 | 当前代码未使用 |

快速示意：

```text
PS2接收器                  STM32F407
------------------------------------------
ATT / CS   -------------> PC0
CMD        -------------> PC1
CLK        -------------> PC2
DAT        <------------- PC3
VCC        -------------> 3.3V
GND        -------------> GND
```

注意事项：

1. 优先使用支持 `3.3V` 供电的 PS2 接收器。
2. 如果你的接收器只能在 `5V` 下工作，必须确认 `DAT` 不会输出 5V 到 STM32。
3. 当前固件把 `START` 定义为“进入 / 退出旁路模式”，把 `SELECT` 定义为“本地急停”。
4. 详细调试步骤和按键映射见 [PS2手柄直连STM32旁路控制指南](/E:/Mech%20Engineering/MyDroid_Innefa/docs/PS2手柄直连STM32旁路控制指南.md)。

## 2. 520电机与L298N驱动模块接线

### 2.1 L298N引脚定义

```
L298N 驱动模块引脚（以常见的双通道模块为例）

        ┌─────────────────┐
     1  │ IN1 (STM32-PA5) │
     2  │ IN2 (STM32-PA6) │
     3  │ GND             │
     4  │ GND             │
     5  │ OUT1 (电机A红)  │
     6  │ OUT2 (电机A黑)  │
    GND │ GND             │
    +12V│ +12V (电源)     │
    GND │ GND             │
    +12V│ +12V (逻辑电源) │
    10  │ IN3 (STM32-PA7) │
    11  │ IN4 (STM32-PB5) │
    12  │ OUT3 (电机B红)  │
    13  │ OUT4 (电机B黑)  │
        └─────────────────┘

连接规则：
- 所有GND脚必须连接（驱动模块、STM32、电源共地）
- IN1/IN2 控制电机A的方向（选一个为使能）
- IN3/IN4 控制电机B的方向
- OUT1/OUT2 接电机A的红黑线
- OUT3/OUT4 接电机B的红黑线
```

## 3. 编码器接线

### 3.1 单个编码器的连接（以520电机为例）

```
520电机编码器         STM32F407
────────────────────────────────
A相 ────────────────► PA0 (TIM2_CH1输入捕获)
B相 ────────────────► PA1 (TIM2_CH2输入捕获)
Z相（霍尔零位）────► PA2（可选中断）
+5V ────────────────► 3.3V供电
GND ────────────────► GND

备注：编码器信号为低电平信号，可直接与STM32输入相连
      若信号噪声严重，可在信号线上加上拉电阻（4.7kΩ-10kΩ）
```

### 3.2 四电机编码器的TIM分配

```
电机         编码器A    编码器B    使用TIM
────────────────────────────────────────
前左(FL)     PA0        PA1        TIM2 QEI模式
前右(FR)     PA6        PA7        TIM3 QEI模式
后左(RL)     PB6        PB7        TIM4 QEI模式
后右(RR)     PC6        PC7        TIM5 QEI模式
```

### 3.3 编码器信号输入的电气特性

```
信噪比影响：
- 编码器输出：0-5V 方波
- STM32输入范围：0-3.3V
- 转换方案A（直连 - 推荐）
  * 编码器5V直接接STM32，需要限流电阻
  * R = (5V - 3.3V) / I_in = 1.7V / 1mA = 1.7kΩ
  * 使用1.5kΩ或2.2kΩ电阻

- 转换方案B（隔离 - 可靠性更高）
  * 使用光隔离器（PC817或4N25）
  * 成本略高，但完全隔离干扰

推荐：使用方案A，加入滤波电容(0.1μF)和上拉电阻(4.7kΩ)的RC滤波网络
```

### 4.3 电流计算与电源容量

```
电流预算（12V驱动）：
- 单个520电机：
  * 无负载空转: 200mA
  * 50%功率: 800mA
  * 100%功率: 2000mA (限流至3500mA)

- 4个电机同时运行：
  * 最坏情况: 4 × 2000mA = 8000mA (8A)
  * 建议电源: 10A以上，留30%余量

电源选择：
  ✓ 不足: USB 2A (5V) + 升压模块 ✗ (容量太小)
  ✓ 适中: USB 3A QC (5V/9V) + 升压 (勉强可用)
  ✓ 推荐: USB 5A QC (5V/9V/12V) 或 12V/3A DC电源
  ✓ 最优: 12V/5A 工业电源 + UPS电池备份

功率计算：
  P = U × I = 12V × 8A = 96W (最坏情况)
  建议选 "12V/10A" 的电源标签
```

## 5. 常见问题排查流程图

```
电机不转？
  ↓
[检查1] 12V电源是否接入？
  ├─ 没接 → 连接电源，检查指示灯
  └─ 接了 → [检查2]
  
[检查2] L298N驱动模块的指示灯是否亮？
  ├─ 不亮 → 检查供电线是否松动
  ├─ 亮但暗 → 可能短路，断电检查
  └─ 亮 → [检查3]

[检查3] STM32是否收到命令？(UART输出)
  ├─ 无输出 → STM32未启动，重新烧录
  ├─ 有输出但电机无反应 → [检查4]
  └─ 命令错误 → 检查UART命令格式

[检查4] PWM波形是否输出？(示波器测量PA5等)
  ├─ 无波形 → TIM配置错误，重新初始化
  ├─ 有波形但电压不对(<3V或>5V) → IN1/IN2GPIO问题
  └─ 波形正常 → [检查5]

[检查5] L298N输出端是否有电压？(测OUT1-OUT2)
  ├─ 无电压 → 驱动芯片故障，更换模块
  ├─ 电压不稳定(闪烁) → 编码器反馈干扰，加隔离
  └─ 电压正常 → [检查6]

[检查6] 电机接线是否正确？
  ├─ 接反了 → 交换电机的红黑线，或软件反向
  ├─ 接触不良 → 清洁接触点，重新插拔
  └─ 电机本身烧毁 → 更换电机

编码器不计数？
  ↓
[检查A] 编码器是否有+5V供电？
  ├─ 测不到5V → 检查电源线，更换降压模块
  └─ 有5V → [检查B]

[检查B] 编码器A/B信号是否接入正确TIM？
  ├─ 接错TIM → 重新接线或修改代码中TIM配置
  └─ 接对了 → [检查C]

[检查C] TIM是否启用QEI模式？(查看CubeMX设置)
  ├─ 未启用 → 在CubeMX中配置"Encoder Mode"
  └─ 已启用 → [检查D]

[检查D] 编码器计数寄存器是否改变？(调试器中看CNT)
  ├─ CNT不变 → 编码器信号无法被TIM读取，检查硬件连接或信号完整性
  ├─ CNT在计数 → 转速计算公式错误，检查RPM计算逻辑
  └─ CNT反向 → 编码器方向相反，交换A/B线或软件取反
```

## 6. 信号完整性测试（无示波器方案）

### 6.1 使用LED指示灯测试

```
准备物品：LED × 4, 电阻 × 4 (330Ω), 面包板

接线：
GPIO_PA5 → 330Ω电阻 → LED正极 → GND

运行测试：
M 0 500 (启动电机0)
观察LED亮度：
  ✓ LED闪烁发光 → PWM信号正确
  ✗ LED常亮或不亮 → PWM故障或占空比过低
  ✗ LED不闪 → 占空比100%或0%(死锁)
```

### 6.2 使用数字万用表测试

```
测量项目：

1. 电源电压
   - 12V电源正极 vs GND: 应读 11.5V ~ 12.5V
   - 3.3V LDO输出 vs GND: 应读 3.2V ~ 3.4V
   
2. GPIO输出电压
   - PA5、PA6 (手动控制M 0 100)
   - 输出应在 0V 和 3.3V 之间变化
   - 如固定在3.3V → GPIO未输出PWM，检查TIM配置
   
3. 编码器信号
   - PA0、PA1 (手动转动电机)
   - 应看到 0V ~ 5V 的方波变化
   - 如固定在某个值 → 编码器故障或没转动
   
4. L298N输出电压
   - OUT1、OUT2 (启动电机后)
   - 应看到 0V 和 12V 之间的切换
   - 频率 ≈ 20000Hz (太快看不见，用万用表应显示~6V平均值)
```

### 6.3 简易故障诊断四步法

```
STEP 1: 通电检查 (无需命令)
├─ 听电机声音: 有微弱嗡嗡声 ? → 驱动器工作
├─ 触摸驱动器: 温温的(不烫) ? → 功率合理
└─ LED指示灯: 是否亮 ? → 供电正常

STEP 2: 命令测试 (M 0 100)
├─ UART有OK响应 ? → 通信正常
├─ PWM LED闪烁 ? → 信号输出正常
└─ 电机微弱转动 ? → 驱动工作

STEP 3: 功率测试 (M 0 500)
├─ 电机明显加速 ? → 功率输出线性
├─ 电流增加(触摸变热) ? → 电流循环正常
└─ 编码器有大脉冲计数 ? → 反馈链路工作

STEP 4: 反向测试 (M 0 -300)
├─ 电机反向 ? → 方向控制正常
├─ 编码器计数减少 ? → 反向识别工作
└─ 无异常噪音/烧焦味 ? → 完整性通过

全通过 → 系统就绪！
任何一步失败 → 根据上面的排查流程定位问题
```

## 7. PCB设计建议（如要定制PCB）

### 7.1 电源管理层

```
推荐用双层或四层PCB：

Layer 1 (信号层):
  - 短线: 编码器信号、UART、PWM
  - 避免长走线跨越不同地区
  
Layer 2 (地层 - GND):
  - 完整的地平面
  - 电机驱动部分单独回地
  
Layer 3 (电源层 - 可选):
  - +5V/+3.3V 平面
  
Layer 4 (信号层底层):
  - 其他信号线

关键走线距离：
  - PWM进入驱动芯片: < 10mm
  - 编码器: 屏蔽走线, > 10mm远离高频PWM
  - UART: 差分走线, 等长
```

## 8. 快速排查决策树（最简洁版）

```
症状          → 第一检查           → 第二检查           → 解决方案
──────────────────────────────────────────────────────────

电机不转      → 12V接了吗?  → L298能驱动吗?  → 检查PWM波形
              → NO: 接电源    → 测IN1/IN2电压   → 重配GPIO

无编码器计数  → 编码器供电?  → TIM QEI启用?   → 加隔离/滤波
              → NO: 接3.3V    → PA0/PA1接对?   → 交换信号线

转速不同步    → 都在转吗?    → 电机损坏吗?    → 加速度补偿
              → NO: 定位坏的   → 手转验证       → 软件校准

UART无通信    → 波特率对吗?  → 线接对吗?      → 更换USB转TTL
              → 115200 设对    → TX→RX, RX→TX  → 检查驱动程序

过热保护      → 长时间满功率? → 散热足吗?     → 降低占空比
              → YES: 降到70%   → 加散热片       → 定时休息
```

## 9. 硬件校准与优化

### 9.1 编码器PPR确认

```
如果520电机标称规格不明确，现场测量PPR：

1. 禁止电机运行时的任何接触 ⚠
2. 手工缓慢旋转电机一周
3. 记录编码器计数增量: CNT_start → CNT_end
4. PPR = CNT_end - CNT_start

典型520电机: PPR = 20 ~ 30
如测得值偏离很大(< 10 或 > 50), 可能:
  - 编码器倍频(4倍): 除法÷4
  - 编码器更精密: 检查规格书
```

### 9.2 速度补偿系数校准

```
四电机转速一致性校准：

1. 所有电机设置相同PWM (M 0-3 500)
2. 各电机转速读数 (E 0-3)
3. 计算补偿: factor = avg_rpm / motor_i_rpm

示例:
  Motor 0: RPM = 240 → factor = 240/240 = 1.00
  Motor 1: RPM = 250 → factor = 240/250 = 0.96
  Motor 2: RPM = 235 → factor = 240/235 = 1.02
  Motor 3: RPM = 245 → factor = 240/245 = 0.98

写入STM32:
  C 0 100  (factor 1.00)
  C 1 96   (factor 0.96)
  C 2 102  (factor 1.02)
  C 3 98   (factor 0.98)
```
