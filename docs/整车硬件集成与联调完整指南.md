| 电机 | PWM | IN1控制 | IN2控制 | 驱动模块 |

| RL后左 | PB0/TIM3_CH3 | PC4 | PC5 | #2 |
| RR后右 | PB1/TIM3_CH4 | PB12 | PB13 | #2 |
| STBY使能 | PB14 | - | - | 共用 |

### 2.3 STM32F103C8T6替代方案

#### 概述
STM32F103C8T6 (俗称"蓝板") 是STM32F407的低成本替代品，具有相同的内核架构但外设较少。适用于原型开发和成本敏感项目。注意：F103C8T6的Flash仅64KB，RAM仅20KB，可能需要优化固件代码。

#### 硬件兼容性
- **UART**: USART1可用 (PA9/PA10)，波特率115200
- **PWM**: TIM1/TIM2/TIM3可用，需重新分配引脚
- **GPIO**: 充足，但需注意复用功能
- **编码器**: TIM2/TIM3可用，TIM4不可用 (F103无TIM4)

#### 引脚映射 (F103C8T6)

##### UART连接
| 功能 | STM32F103引脚 | ROCK 3B引脚 | 标准 |
|------|--------------|-----------|------|
| UART RX | PA10 | GPIO TX | TTL 3.3V |
| UART TX | PA9 | GPIO RX | TTL 3.3V |
| GND | GND | GND | **必须共地** |

##### 电机PWM和方向控制
| 电机 | PWM引脚 | TIM通道 | IN1控制 | IN2控制 | 驱动模块 |
|------|--------|--------|--------|--------|--------|
| FL前左 | PA8 | TIM1_CH1 | PB12 | PB13 | #1 |
| FR前右 | PA9 | TIM1_CH2 | PB14 | PB15 | #1 |
| RL后左 | PA10 | TIM1_CH3 | PA0 | PA1 | #2 |
| RR后右 | PA11 | TIM1_CH4 | PA2 | PA3 | #2 |
| STBY使能 | PB11 | - | - | - | 共用 |

**注意**: F103的TIM1是高级定时器，支持PWM输出。PA9/PA10与UART1复用，需在代码中配置。

##### 舵机控制
| 功能 | STM32F103引脚 | TIM通道 | 信号 | 电源 |
|------|--------------|--------|------|------|
| Pan舵机 | PB6 | TIM4_CH1 | PWM | 外部5V |

**注意**: F103C8T6无TIM4！需使用TIM3_CH1 (PB4) 或其他可用通道。

##### 编码器反馈 (F103C8T6)
| 电机编码器 | A线 | B线 | TIM | 模式 | 备注 |
|----------|-----|-----|-----|------|------|
| FL | PA0 | PA1 | TIM2 | QEI | 与RL方向控制复用，需软件切换 |
| FR | PA6 | PA7 | TIM3 | QEI | - |
| RL | PB6 | PB7 | TIM4 | QEI | F103无TIM4！需用TIM1备用通道 |
| RR | PC6 | PC7 | - | - | F103无PC6/PC7，需改用PA15/PB3 |

#### 连线调试步骤

##### Step 1: 硬件连接检查
```
STM32F103C8T6 引脚连接:
- PA9 (TX) → ROCK3B RX
- PA10 (RX) ← ROCK3B TX  
- GND → GND (共地)

电机驱动:
- PA8 → L298N #1 IN1 (FL PWM)
- PB12 → L298N #1 IN2 (FL DIR1)
- PB13 → L298N #1 IN3 (FL DIR2)
- PA9 → L298N #1 IN4 (FR PWM) [UART复用注意!]
- PB14 → L298N #1 IN5 (FR DIR1)
- PB15 → L298N #1 IN6 (FR DIR2)

舵机:
- PB4 → Pan舵机信号 (使用TIM3_CH1)
- 5V → 舵机电源
- GND → 舵机地
```

##### Step 2: 固件适配
```c
// 在STM32CubeMX中配置:
// 1. TIM1: PWM Generation CH1-4 (PA8/PA9/PA10/PA11)
// 2. TIM3: PWM Generation CH1 (PB4) 用于舵机
// 3. TIM2: Encoder Mode (PA0/PA1) 用于FL编码器
// 4. TIM3: Encoder Mode (PA6/PA7) 用于FR编码器
// 5. USART1: Async 115200bps (PA9/PA10) [与PWM复用!]

// 代码修改:
// app_config.h 中更新引脚定义
#define MOTOR_FL_PWM_PIN     GPIO_PIN_8
#define MOTOR_FL_PWM_PORT    GPIOA
#define MOTOR_FL_DIR1_PIN    GPIO_PIN_12
#define MOTOR_FL_DIR1_PORT   GPIOB
// ... 其他电机类似

// 舵机改用TIM3
#define PAN_SERVO_TIM        htim3
#define PAN_SERVO_CHANNEL    TIM_CHANNEL_1
```

##### Step 3: UART复用问题解决
PA9/PA10同时用于UART和PWM，需动态切换：
```c
// 发送UART前关闭PWM
HAL_TIM_PWM_Stop(&htim1, TIM_CHANNEL_2); // PA9
// 发送完成后重新启动PWM
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_2);
```

##### Step 4: 编码器引脚重映射
由于F103引脚限制：
```c
// RL编码器改用TIM1备用 (但TIM1用于PWM，冲突!)
// 建议: 暂时移除RL/RR编码器，或用软件模拟
// 或者升级到F103C8T6的48脚版本获取更多引脚
```

##### Step 5: 调试验证
```bash
# 烧录固件后测试
python3 tools/motor_test_tool.py --port /dev/ttyS1 --baud 115200

# 预期: UART通信正常，电机PWM可控
# 注意: 编码器反馈可能不完整
```

#### 限制与建议
- **Flash空间**: F103仅64KB，固件需精简
- **无FPU**: 浮点运算慢，运动学计算可能需优化
- **引脚复用**: UART与PWM冲突，需软件管理
- **编码器**: 仅支持FL/FR，RL/RR需外部扩展
- **推荐**: 仅用于原型验证，最终产品建议使用F407或更高系列

import serial
import sys

ser = serial.Serial('/dev/ttyS1', 115200, timeout=1)
while True:
    data = ser.read(16)  # 读取一帧 (16字节)
    if data:
        hex_str = ' '.join(f'{b:02x}' for b in data)
        print(f"Frame: {hex_str}")
        # 验证帧头
        if data[0] == 0xAA and data[1] == 0x55:
            print("  ✓ Frame header OK")

ser.close()
EOF

### 4.1 按现象快速定位

突然停止                过流保护/CRC错     4.2.8

### 4.2 分类排查方案

#### 4.2.1 系统启动就停止

**现象**: STM32上电后, LED无反应或立即停止

**检查流程**:

```
┌─ 有无PC端log输出?
│  ├─ 无 → STM32没通电或USB没接好
│  │      检查USB线, 确认PC能识别开发板
│  │
│  └─ 有 → 
│     ├─ 有Exception错误?
│     │  └─ 是 → 硬故障, 检查电路或更换板
│     │
│     └─ 无Exception?
│        └─ 看日志最后一条消息在哪里
│           └─ 在 SystemClock_Config() → 时钟配置错
│           └─ 在 MX_GPIO_Init() → GPIO冲突
│           └─ 在 MX_TIM_Init() → TIM配置错
│           └─ 在 MotorTest_Init() → 电机模块崩溃
```

#### 4.2.2 UART无通信

**现象**: serial_bridge_node 连不上 `/dev/ttyS1`, 或连上但无数据

**快速诊断**:

```bash
# 1. 确认设备存在
ls -la /dev/ttyS*
# 应该看到 /dev/ttyS1

# 2. 尝试用其他工具通信
screen /dev/ttyS1 115200
minicom -D /dev/ttyS1

# 3. 如果screen黑屏但没断开, UART物理链路可能有问题
# 检查:
# - TX/RX是否接反? (ROS侧TX→STM32侧RX, 反之亦然)
# - GND是否共接?
# - 线是否接触不良?
# - 波特率是否都设为115200?

# 4. 如果screen能显示但乱码, 说明波特率不匹配

# 5. 查看STM32侧UART配置
# STM32CubeIDE → Peripherals → USART1
# Mode: Asynchronous
# Baud Rate: 115200
# Word Length: 8 Bits
# Parity: None
# Stop Bits: 1
```

#### 4.2.3 底盘不转

**现象**: 发送电机命令但没有反应

**排查树状图**:

```
底盘不转
├─ 有无PWM波形?(用示波器)
│  ├─ 无波形
│  │  └─ TIM初始化有问题
│  │     □ CubeMX中TIM3是否设为PWM Output
│  │     □ 否则改为PWM并重新生成代码
│  │
│  └─ 有波形
│     ├─ 方向脚(IN1/IN2)电压是否正确?
│     │  ├─ 无电压 → GPIO没输出, 检查app_config.h中的定义
│     │  ├─ 固定3.3V → GPIO输出了但方向错, 交换IN1/IN2
│     │  └─ 变化0-3.3V → 正常
│     │
│     └─ L298N OUT输出是否有12V?
│        ├─ 无 → 驱动芯片故障, 更换L298N或用万用表测IN脚
│        └─ 有但电机不转 → 电机烧毁, 手工旋转测试
```

#### 4.2.4 四轮转速偏差大

**现象**: 直线前进时底盘偏角, 或编码器读数差异>10%

**处理顺序**:

```
1. 排除电机问题
   □ 所有电机都能转?(都转 → 归一化算法问题)
   □ 空载转速差异?(>20% → 电机参数差异大)
   
2. 校准电机补偿系数
   □ 记录各电机的RPM
   □ 用电机测试工具的 C 命令设置补偿
   
3. 检查轮子安装
   □ 四个轮子滚子方向一致?
   □ 轮子夹角是否标准(45°)?
   □ 轮子离地间隙是否均匀?
```
