# 底盘电机驱动独立测试方案

## 1. 硬件配置与接线方案

### 1.1 系统组成

```
┌─────────────────┐         ┌──────────────────┐         ┌──────────────────┐
│  Radxa ROCK 3B  │◄────────►│   STM32F4xx      │◄───┬───►│  520电机驱动模块 │
│                 │  USB-TTL │   (下位机)       │    │    │   (L298N/DRV8835)│
│  - GPIO         │  或 UART │                  │    │    │                  │
│  - Python脚本   │          │  - PWM控制       │    │    │  × 4 个520电机  │
└─────────────────┘          │  - 方向控制      │    │    │  × 4 个编码器   │
                             │  - 编码器读取    │    │    └──────────────────┘
                             │  - CAN/UART      │    │
                             └──────────────────┘    │
                                     ▲               │
                                     │               │
                            ┌────────┴───────────┐   │
                            │   12V 电源模块    │◄──┘
                            │   (5A 以上)        │
                            └────────────────────┘
```

### 1.2 硬件选型建议

#### 电机驱动模块
- **推荐方案1：L298N双通道驱动模块**
  - 优点：成熟可靠，易于获取，价格便宜
  - 额定电流：2A/通道（可并联提升到4A）
  - 工作电压：5V-35V
  - 接线简单，方向控制需要2个GPIO
  - 每个L298N驱动2个电机，共需2个模块

- **推荐方案2：DRV8835/TB6612驱动芯片（推荐性价比优先）**
  - DRV8835：单通道3A，小巧轻便
  - TB6612：双通道2A，集成度高
  - 优点：集成度高，发热量少，可靠性高
  - 缺点：焊接要求较高

#### 编码器反馈
- 520电机标配编码器（通常为光学编码器）
- 输出：A、B两路脉冲信号（正交编码）+ 一路Index/Z（可选）
- 单圈分辨率：通常为20-30 CPR（counts per revolution）
- STM32应使用TIM输入捕获或QEI模式读取

#### 电源配置
```
12V 主电源 (≥5A)
    ├─┬─ 电机驱动模块输入 (12V, ~4A)
    │ │
    │ └─ 5V降压模块 (1A) ──► STM32开发板 (USB供电)
    │                    ──► 编码器信号隔离电源 (3.3V, 500mA)
    │
    └─ 地线 (GND，必须共地)
```

### 1.3 连接示意图（以L298N为例）

#### 电机驱动接线

```
520电机 ×4                L298N (模块1)           STM32F4xx
                    
前左电机 (FL)  ────┐     IN1 ◄──────────────────► PA5  (GPIO)
            Motor─┼──┬──► IN2 ◄──────────────────► PA6  (GPIO)
            +12V──┘  │   OUT1 ──┐
                     │   OUT2 ──●─────────► FL电机红线
                     │ 
                     └──► +12V, GND (电源)

前右电机 (FR)  ────┐     IN3/IN1 ◄──────────────► PA7  (GPIO)
            Motor─┼──┬──► IN4/IN2 ◄──────────────► PB5  (GPIO)
            +12V──┘  │   OUT3/OUT1 ──┐
                     │   OUT4/OUT2 ──●─────────► FR电机红线
                     │ 
                     └──► +12V, GND (电源)

[L298N模块2 类似接线 后轮 RL, RR]
```

#### 编码器接线

```
520电机编码器       STM32F4xx

  A ─────────────► PA0  (TIM2_CH1, QEI模式)
  B ─────────────► PA1  (TIM2_CH2, QEI模式)
  +5V ───────────► 3.3V (或独立5V供电)
  GND ───────────► GND
  Z (可选) ──────► PB0  (外部中断, 霍尔零位)

[4个电机编码器均需类似连接，使用不同的TIM端口]
```

#### 串口连接（测试通信）

```
Radxa ROCK 3B          STM32F4xx

GPIO TX ────────────────► USART1_RX (PA10)
GPIO RX ────────────────► USART1_TX (PA9)
GND ─────────────────────► GND
```

或使用USB转TTL模块代替GPIO直接连接。

### 1.4 电源接线检查清单

- [ ] 12V电源正极 → L298N模块 +12V
- [ ] GND 共接：电源、STM32、电机驱动模块
- [ ] 5V降压模块 → STM32开发板 +5V
- [ ] 编码器 +5V（如需隔离，使用独立降压模块）
- [ ] 编码器信号线（A/B/Z）接STM32对应GPIO
- [ ] 确认所有信号地线相连

## 2. STM32固件设计

### 2.1 测试固件框架

目标：
- 独立运行，不依赖ROS2或上位机
- 支持UART收发简单命令
- 可进行单电机测试
- 可读取编码器反馈

### 2.2 关键模块

```c
// motor_test.h - 测试电机的简化接口

typedef struct {
    uint8_t motor_id;      // 0: FL, 1: FR, 2: RL, 3: RR
    int16_t pwm_duty;      // -1000~1000
    uint32_t encoder_count;  // 编码器计数
} MotorStatus;

void MotorTest_Init(void);
void MotorTest_SetMotor(uint8_t id, int16_t duty);
void MotorTest_StopAll(void);
MotorStatus MotorTest_GetStatus(uint8_t id);
void MotorTest_CalibrateEncoder(uint8_t id);
```

### 2.3 编码器读取模式

**推荐：QEI（正交编码器接口）模式**

```c
// 使用STM32 TIM的 QEI 配置
// TIM2: FL 和 FR 编码器 (PA0, PA1)
// TIM3: RL 和 RR 编码器 (PA6, PA7)

// 编码器计数 = TIM->CNT （STM32自动计算）
// 编码器方向 = TIM->CR1.DIR

// 采样周期：10ms
// 计算角速度：
uint32_t current_count = __HAL_TIM_GET_COUNTER(&htim2);
float rpm = ((current_count - last_count) * 6000) / PPR;  
// PPR = pulses per revolution (20-30 typical)
```

## 3. 测试步骤

### 3.1 硬件检验（烧录前）

1. **断电状态下检查**
   - [ ] 用万用表检查电源正负极（12V）
   - [ ] 确认电机与驱动模块接线无误
   - [ ] 确认编码器信号线接入正确GPIO
   - [ ] 确认GND共接无断开

2. **上电后检查（无电机运转）**
   - [ ] 万用表测L298N OUT管脚，应为低电平（未激活）
   - [ ] 万用表测TIM相关GPIO，应为低电平
   - [ ] 无异味、无冒烟、无过热

### 3.3 单电机测试

#### 步骤A: 空载测试（无负载）

1. 启动STM32固件
2. 通过UART发送命令：`M 0 200`（电机0，PWM 20%）
3. **预期行为**：
   - 前左电机缓慢转起
   - 编码器计数单调递增
   - 电流 < 1A（空载）

4. 逐步增加PWM：200 → 500 → 800
   - 观察电机转速变化是否线性
   - 观察编码器计数变化

5. 测试反向：`M 0 -300`
   - 电机应反向
   - 编码器计数应递减

#### 步骤B: 控制精度测试

```
测试序列：
1. M 0 0   (停止，编码器计数冻结)
2. 记录 count_stop = 1000
3. M 0 500 (前进20%功率)
4. 延迟 1000ms
5. 记录 count_run = 2500
6. 计算：Δcount = 1500，预期 > 200 (20%功率下应有明显动作)
```

#### 步骤C: 电流监控（可选，需要电流表或示波器）

```
空载时：< 0.5A
20% PWM: 0.8-1.2A
50% PWM: 1.5-2.0A
80% PWM: 2.5-3.0A (不应超过驱动器额定值)
```

### 3.4 四电机同步测试

```uart命令
M 0 500     # 前左 50% 前进
M 1 500     # 前右 50% 前进
M 2 500     # 后左 50% 前进
M 3 500     # 后右 50% 前进

延迟 2 秒后观察：
- 四电机转速是否一致？
- 编码器计数增长速率是否接近？
- 是否有电机启动滞后或过快？
```

### 3.5 编码器精度验证

```python
# on Radxa ROCK 3B (上位机)

import serial
import time

ser = serial.Serial('/dev/ttyUSB0', 115200, timeout=1)

def send_cmd(cmd):
    ser.write(cmd.encode() + b'\n')
    response = ser.readline().decode()
    return response

# 测试编码器
for motor_id in range(4):
    send_cmd(f"M {motor_id} 500")  # 启动电机
    time.sleep(2)
    
    # 读取编码器
    response = send_cmd(f"E {motor_id}")  # 获取计数
    count = int(response.strip())
    
    rpm = count / 20 * 30  # 假设PPR=20，采样周期30ms
    print(f"Motor {motor_id}: Count={count}, RPM≈{rpm}")
    
    send_cmd(f"M {motor_id} 0")  # 停止
```

## 4. 常见问题排查

### 问题1: 电机不转，无编码器反馈

**原因排查**
1. [ ] 12V电源是否连接？ → 检查电源指示灯
2. [ ] 电机驱动模块是否进入保护模式？ → 切断电源重启
3. [ ] PWM指令是否正确发送？ → 用示波器测量TIM引脚波形
4. [ ] GPIO方向控制是否正确？ → 用万用表测IN1/IN2高低电平
5. [ ] 电机本身损坏？ → 替换测试电机或手动转动感受

**解决方案**
```c
// 强制启用L298N使能脚（如有）
HAL_GPIO_WritePin(MOTOR_EN_GPIO_Port, MOTOR_EN_Pin, GPIO_PIN_SET);

// 检查PWM是否输出
if (__HAL_TIM_GET_COMPARE(&htim2, TIM_CHANNEL_1) == 0) {
    // PWM异常，设置最小值
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 100);
}
```

### 问题2: 编码器计数不增加

**原因排查**
1. [ ] 编码器信号线是否松动？ → 重新插拔连接器
2. [ ] STM32的TIM外设是否启用QEI模式？ → 检查CubeMX配置
3. [ ] TIM频率是否过低（无法检测脉冲）？ → 增加TIM时钟或滤波周期
4. [ ] 编码器供电不足？ → 编码器LED是否亮？

**解决方案**
```c
// 检查TIM配置
MX_TIM2_Init();  // 重新初始化
__HAL_TIM_ENCODER_START(&htim2, TIM_CHANNEL_ALL);

// 验证计数是否变化
uint32_t old_count = __HAL_TIM_GET_COUNTER(&htim2);
HAL_Delay(100);
uint32_t new_count = __HAL_TIM_GET_COUNTER(&htim2);
if (new_count == old_count) {
    // 编码器不计数，检查硬件连接
}
```

### 问题3: 电机启动困难（需要很高PWM才能动）

**原因**
- 摩擦力过大：检查轴承、减速器
- 电源不足：12V电压下降到9V以下？检查电源和连接线
- 驱动芯片发热保护：触发电流限制

**解决方案**
```
1. 检查电源：万用表量取电源电压，应 ≥ 11.5V（12V供电）
2. 检查连接：所有接线是否接触不良，换粗导线
3. 降低启动PWM最小值（在motor_control.c中调整 MOTOR_PWM_MIN_EFFECTIVE_COUNTS）
```

### 问题4: 四电机转速不一致

**原因**
- 电机参数散差（正常情况）
- 传动系统有差异（齿轮啮合、轴承磨损）
- PWM输出值有偏差

**校准方案**
```c
// 在基础PWM上加补偿系数
typedef struct {
    float fl_factor;  // 前左补偿 = 0.95
    float fr_factor;  // 前右补偿 = 1.00
    float rl_factor;  // 后左补偿 = 1.02
    float rr_factor;  // 后右补偿 = 0.98
} MotorCalibration;

// 实际PWM = 目标PWM × 补偿系数
int16_t actual_duty = (int16_t)(desired_duty * motor_calib.fl_factor);
```
